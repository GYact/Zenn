## 「その音声合成、月額課金する前にローカルで動く」

通知の読み上げ、動画のナレーション、社内デモの吹き替え——ちょっとした音声合成のためだけに ElevenLabs のサブスクを契約していないだろうか。2026年4月に GitHub Trending 1位を獲得した [jamiepine/voicebox](https://github.com/jamiepine/voicebox) は、Alibaba の Qwen3-TTS を使い、数秒のサンプル音声だけでボイスクローンをローカル完結させる OSS だ。MIT ライセンス・TypeScript製・約45.6k stars(2026年4月時点)。API キーもレート制限もなく、自分のマシンの中だけで完結する。

この記事では実際に手を動かして「clone → REST API 化 → 自前スクリプトから叩く」までを一気通貫でやる。GUI を触るだけでは終わらせず、**自動化パイプラインに組み込める形**まで持っていくのがゴールだ。

## 背景: なぜ Tauri + FastAPI という構成なのか

voicebox のアーキテクチャは以下の3層でできている。

- `app/` — React 製フロントエンド(共通 UI)
- `tauri/` — デスクトップアプリの殻(Tauri + Rust)
- `backend/` — Python(FastAPI)の音声合成サーバ。Tauri がサイドカープロセスとして起動・管理する

つまり GUI はあくまで「入り口」で、実体は `127.0.0.1:17493` で待ち受ける REST API サーバだ。デスクトップアプリを起動した状態なら、そのままローカル HTTP API として外部スクリプトからも叩ける。ここが実装記事として面白いポイントで、GUI 専用ツールではなく **音声合成の自前バックエンドとして流用できる**。

## セットアップ手順

前提として Bun / Rust / Python 3 が必要になる(GUI が Tauri、TTS 推論部分が Python という構成のため)。

```bash
# 1. clone
git clone https://github.com/jamiepine/voicebox.git
cd voicebox

# 2. JS/Rust 側の依存関係
bun install

# 3. Python(FastAPI + Qwen3-TTS)側の依存関係
cd backend
pip install -r requirements.txt
cd ..

# 4. 開発モードで起動(デスクトップUI + バックエンドAPIが同時に立ち上がる)
bun run dev
```

Makefile 経由でもよい(`make setup && make dev`)。GPU がある環境では推論が明確に速くなるが、CPU のみでも動作する(数秒〜十数秒/文の体感)。

起動できたかどうかは、ブラウザで以下を開いて確認する。

```
http://localhost:17493/docs
```

FastAPI 標準の Swagger UI が開き、`/generate` `/speak` `/transcribe` `/profiles` など約90個のエンドポイントが並んでいれば成功だ。

## 声をクローンする

音声プロファイルの作成(=クローン)は、起動したデスクトップ UI 上で数秒〜数十秒の音声サンプルをアップロードして行う。API 経由でのプロファイル新規作成エンドポイントは今回のドキュメント範囲では確認できなかったため、**クローン自体は GUI・生成の自動化は API** という役割分担で進めるのが実践的だ。

UI でクローンが完了したら、作成した `profile_id` を API から確認する。

```bash
curl http://127.0.0.1:17493/profiles
```

レスポンスの JSON に含まれる `id` が、以降の `/generate` 呼び出しで使う `profile_id` になる。

## 自動化スクリプトを書く

ここからが本題。ナレーション原稿(複数行のテキスト)を1本ずつ音声化し、連番ファイルとして保存する Python スクリプトを書く。

```python
import requests
from pathlib import Path

API = "http://127.0.0.1:17493"
PROFILE_ID = "abc123"  # /profiles で確認した自分のプロファイルID
OUT_DIR = Path("output")
OUT_DIR.mkdir(exist_ok=True)

scripts = [
    "本日のリリースノートをお読みします。",
    "まず、認証まわりの不具合を修正しました。",
    "次に、ダッシュボードの表示速度を改善しました。",
]

for i, text in enumerate(scripts, start=1):
    res = requests.post(
        f"{API}/generate",
        json={"text": text, "profile_id": PROFILE_ID, "language": "ja"},
        timeout=120,
    )
    res.raise_for_status()
    out_path = OUT_DIR / f"line_{i:02d}.wav"
    out_path.write_bytes(res.content)
    print(f"saved: {out_path}")
```

生成した `.wav` を `ffmpeg -f concat` で結合すれば、そのまま1本のナレーション音声になる。CI のリリース通知や、社内向け動画のナレーション生成をこのスクリプト1本で完結させられるのが、ローカル完結型 OSS の強みだ。外部 API のようにレート制限やコストを気にせず、何百行でも回せる。

## まとめ

voicebox は GUI だけ見ると「個人向けの音声クローンアプリ」に見えるが、中身は素直な FastAPI サーバであり、`bun run dev` で起動した後は普通の REST API として自動化パイプラインに組み込める。ボイスクローンという「一発ネタ」で終わらせず、通知読み上げやナレーション生成のバッチ処理まで持っていけるかどうかが、このツールを実務で使えるかの分かれ目だ。まずは自分の声を数秒録音して `/profiles` に登録するところから試してみてほしい。
