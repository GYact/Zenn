## 「MCPサーバーって、結局自分でも作れるの?」

Claude Code に MCP サーバーを繋ぐ記事はよく見かけるが、「使う」側の話ばかりで「作る」側の情報は意外と少ない。筆者は自分のプロジェクトで社内 API 連携用の MCP サーバーを自作して Claude Code に繋いだことがあるが、最初につまずいたのは実装の難しさではなく「`console.log` を1行書いただけでサーバーが沈黙する」という地味な罠だった。

この記事では、その経験を踏まえて **ゼロから MCP サーバーを実装し、Claude Code に登録して実際に呼び出すまで** を、コピペで動かせるコード付きで手順化する。所要時間は環境構築込みで 30 分程度。

## 背景: なぜ自作する価値があるか

MCP(Model Context Protocol)は LLM とツール/データソースを繋ぐ標準プロトコルで、Anthropic が提唱し、現在は Claude だけでなく複数のクライアントで採用されている。公式 TypeScript SDK である `@modelcontextprotocol/sdk` は 2026-08 時点で `1.30.0` が最新の安定版(`latest` タグ)として公開されている([npm](https://www.npmjs.com/package/@modelcontextprotocol/sdk))。既製の MCP サーバーは Slack や GitHub など汎用サービス向けが中心で、**社内 API・自作スクリプト・独自の集計ロジックといった「自分たちだけのツール」を LLM に渡す場合は自作するしかない**。ここが自作の一番の動機になる。

## 実装手順

### 1. プロジェクトを作る

```bash
mkdir my-mcp-server && cd my-mcp-server
pnpm init
pnpm add @modelcontextprotocol/sdk zod
pnpm add -D typescript tsx @types/node
```

`tsconfig.json` は ESM + Node18 相当で最小限にする。

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "outDir": "dist"
  },
  "include": ["src"]
}
```

### 2. サーバー本体を書く

題材は「指定ディレクトリ配下の `TODO` / `FIXME` コメントを一覧するツール」にする。地味だが、AI エージェントに渡すと実際に役立つ実用例だ。

```typescript
// src/index.ts
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";
import { readdir, readFile } from "node:fs/promises";
import { join, extname } from "node:path";

const server = new McpServer({
  name: "todo-scanner",
  version: "1.0.0",
});

const TARGET_EXT = new Set([".ts", ".tsx", ".js", ".py"]);

async function scan(dir: string): Promise<string[]> {
  const hits: string[] = [];
  const entries = await readdir(dir, { withFileTypes: true });

  for (const entry of entries) {
    if (entry.name === "node_modules" || entry.name.startsWith(".")) continue;
    const path = join(dir, entry.name);

    if (entry.isDirectory()) {
      hits.push(...(await scan(path)));
      continue;
    }
    if (!TARGET_EXT.has(extname(entry.name))) continue;

    const text = await readFile(path, "utf-8");
    text.split("\n").forEach((line, i) => {
      if (/TODO|FIXME/.test(line)) {
        hits.push(`${path}:${i + 1}: ${line.trim()}`);
      }
    });
  }
  return hits;
}

server.registerTool(
  "list_todos",
  {
    title: "List TODO/FIXME comments",
    description: "指定ディレクトリ配下のソースコードから TODO/FIXME コメントを一覧する",
    inputSchema: { dir: z.string().describe("スキャン対象のディレクトリパス") },
  },
  async ({ dir }) => {
    const hits = await scan(dir);
    return {
      content: [
        {
          type: "text",
          text: hits.length ? hits.join("\n") : "TODO/FIXME は見つかりませんでした",
        },
      ],
    };
  },
);

const transport = new StdioServerTransport();
await server.connect(transport);
```

ここで最初に触れた罠が効いてくる。**stdio transport はプロセスの `stdout` をそのまま JSON-RPC のやり取りに使う。** デバッグ目的で `console.log()` を仕込むと、その出力がプロトコルのメッセージに混入してクライアント側がパースエラーで沈黙する。ログを出したいときは必ず `console.error()`(stderr)を使うこと。これは MCP サーバー実装で最初にハマる人が多いポイントだ。

### 3. ローカルで単体動作確認する

Claude Code に繋ぐ前に、公式の MCP Inspector で単体テストするのが早い。

```bash
npx @modelcontextprotocol/inspector npx tsx src/index.ts
```

ブラウザが開き、`list_todos` ツールのスキーマと戻り値をその場で叩いて確認できる。ここで期待通りの JSON が返らないなら、Claude Code に繋ぐ前に直しておく。

### 4. Claude Code に登録する

```bash
claude mcp add todo-scanner -- npx tsx /absolute/path/to/my-mcp-server/src/index.ts
```

`--` の後ろがサーバー起動コマンドで、Claude Code はセッション開始時にこれを子プロセスとして spawn し、`stdio` 経由でツール一覧を問い合わせる。登録内容は `claude mcp list` で確認できる。

### 5. 実際に呼んでみる

Claude Code のチャットで「このリポジトリの `src/` 配下の TODO を一覧して」のように依頼すると、`list_todos` ツールが自動的に選択されて呼び出される。ツールの `description` は LLM がいつこのツールを使うべきかを判断する材料になるので、ここは省略せず具体的に書くのが精度に直結する。

## つまずきやすいポイントまとめ

- **`console.log` 禁止**: stdio サーバーでは stdout はプロトコル専用。ログは `console.error` へ。
- **`inputSchema` は Zod で厳密に**: 型が緩いとクライアント側の引数生成が安定しない。
- **相対パス渡しに注意**: `claude mcp add` に渡すエントリポイントは絶対パスにしておくと、Claude Code の起動ディレクトリに依存せず動く。
- **プロセスが残ることがある**: サーバーを停止せずに Claude Code を終了すると子プロセスが残留するケースがある。開発中は `ps aux | grep tsx` で確認する癖をつけると安心。

## まとめ

MCP サーバーの自作は、SDK が `McpServer` + `registerTool` + `StdioServerTransport` という 3 点セットに集約されているため、思っているより身構える必要はない。今回の `list_todos` のような小さなツールでも、自分たちの開発フローに合わせて LLM に渡せる情報を増やせる。まずは 1 ツールだけの最小サーバーを作って `claude mcp add` で繋いでみるところから始めるのがおすすめだ。
